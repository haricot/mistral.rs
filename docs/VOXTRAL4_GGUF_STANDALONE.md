## B0 — structural binding contract

- Recognize GGUF general.architecture voxtral4 and voxtral4b without
  advertising either as a normal text-only architecture in --arch.
- Validate bounded, explicit Voxtral audio and LLM layer counts.
- Map CrispASR names to the native Voxtral encoder, projector, embedding,
  decoder, and adaptive-RMSNorm weight names.
- Fail on missing required tensors instead of silently accepting them.
- Isolate changes on a standalone master-derived branch.
- Run model-free CPU tests before advancing.

## What B0 does not do

This branch DOES NOT YET transcribe from GGUF. The original native Voxtral
loader expects params.json and native audio/streaming processing. CrispASR
stores its Tekken vocabulary in tokenizer.tekken.vocab_tensor as floats,
and its Slaney mel filters and Hann window as tensors. The GGUF Q4_K data
must be connected to the native pipeline without losing the audio/token
alignment, RoPE conventions, or adaptive norm behavior.

## B2-C1 Rust Tekken tokenizer (under CI)

The dedicated mistralrs-core/src/gguf/voxtral4_tokenizer.rs module reads
the GGUF embedded Tekken F32 byte payload, parses 150000 serialized ranks,
retains only 130072 active ranks, checks all 256 single-byte seeds, and
implements the ranked BPE merge, special-token scanner and pretoken splitting
as deployed in CrispASR src/voxtral4b.cpp.

This reference pretokenizer is **not** the full Unicode tekken.json regex.
Agreement with CrispASR requires a separately generated corpus and C++/Rust
ID-by-ID differential harness. Do not confuse structural ID bounds or
synthetic Rust unit tests with actual GGUF tokenizer parity.

Optional real model test (no GPU):

    VOXTRAL4_GGUF_PATH="$MODEL" cargo test --locked -p mistralrs-core \
      --lib gguf::voxtral4_tokenizer -- --nocapture

GGUF quantized/audio forward remains NOT_VALIDATED.


## B2-C2 — independent C++/Rust token-ID parity (2026-10-17)

CrispASR reference:
- Git commit 369029c91d90a61d8346b8bbdafe426bfdde76d1.
- src/voxtral_tekken_vocab.h Git blob
  66a3a97a74adf94b2b177e41552cd0130e90fd58.
- tools/voxtral4_gguf_cpp_oracle.cpp compiles the *original* pinned
  CrispASR rank-based BPE decoder and its Unicode-aware reference
  pretokenizer. For the deployed voxtral4b path, a separate byte-class
  pretokenizer is reproduced from CrispASR src/voxtral4b.cpp.

The model-free hosted CI compiles the pinned C++ oracle and runs the Rust
unit tests; it cannot prove real-GGUF ID parity without the user's checkpoint.

The real-checkpoint differential script:
- Reads only the GGUF Tekken F32 asset, 1000 special tokens and metadata.
- Re-validates B2-B and the full packed-vocabulary SHA-256.
- Compiles a CPU-only C++ reference against a Git-blob-verified header.
- Compares all 30 fixed French/multilingual/technical corpus entries,
  in order, ID-by-ID, through the Rust tokenizer against the C++ deployed
  runtime's Tekken tokenizer.
- Separately measures divergence between the deployed C++ pretokenizer and
  the richer Unicode pretokenizer from the same pinned header, *without*
  conflating the two implementations.
- Fails on every Rust-vs-deployed-C++ token-ID mismatch.

Run from the root of a clean Voxtral4 GGUF worktree:

    MODEL="$HOME/.cache/huggingface/hub/models--cstr--voxtral-mini-4b-realtime-GGUF/snapshots/1c61dc461970d53264d784363b31ca113c7e01fd/voxtral-mini-4b-realtime-q4_k.gguf"
    python3 -B tools/voxtral4_gguf_cpp_parity.py "$MODEL" \
      --report voxtral4-b2c2-report.json

It downloads just the pinned 17 KB C++ reference header from GitHub,
and verifies its exact Git blob SHA before compilation. For offline runs,
supply --reference-header /path/to/CrispASR/src/voxtral_tekken_vocab.h;
the SHA check is identical.

Acceptance: B2C2_DEPLOYED_CRISPASR_PARITY_PASS_UNICODE_PARITY_NOT_ESTABLISHED.
This is not full Mistral Tekken parity, and cannot promote GGUF audio
inference or the Extended workflow. The later qualification must compare
with official Mistral tokenization and actual Q4_K speech inference.


## B3-A — native multimodal transport (2026-10-17)

Implemented branch-local dispatch for general.architecture = voxtral4 or
voxtral4b from the normal GGUF path into load_native_multimodal, with no
extra --mmproj file required for this all-in-one converter.
It reuses MultimodalLoaderType::Voxtral / VoxtralLoader and
GgufWeightSource sharded_var_builder, with all 711 converter weight bindings.

The native params.json and GGUF architecture metadata are compared
dimension-by-dimension (audio, decoder, RoPE, adaptive normalization,
projection and signal settings). No separate Voxtral inference engine
exists in this branch.

**Tokenizer safety gate:** the packed F32 GGUF Tekken BPE representation is
not the generic tokenizer.ggml.tokens format. B3-A requires a native
tokenizer.json from the original Voxtral checkpoint, matching all 1000
GGUF special IDs, and at most 131072 addressable token IDs. This rejects
an oversized unfiltered 150000-rank tokenizer rather than risking illegal
GGUF embedding lookups. An embedded GGUF -> HuggingFace Tokenizers bridge
that guarantees the active-rank cap is still needed if the original
tokenizer does not meet this invariant.

First run B3-A CPU native configuration preflight, using the real GGUF
and original native model params.json:

    VOXTRAL4_GGUF_PATH="$MODEL" \
      VOXTRAL4_NATIVE_PARAMS="/path/to/original/params.json" \
      cargo test --locked -p mistralrs-core --lib \
      gguf::voxtral4_config -- --nocapture

Experimental native VoxtralLoader direct weight load (NOT QUALIFIED):

    ./target/release/mistralrs serve \
      -m cstr/voxtral-mini-4b-realtime-GGUF \
      -f voxtral-mini-4b-realtime-q4_k.gguf \
      --tok-model-id mistralai/Voxtral-Mini-4B-Realtime-2602

If params.json or the 1000 special-token contract is missing, the
adapter fails closed with an explicit diagnostic. This command has NOT
passed a real Q4_K forward or a French WAV test. Do not enable this
branch in the Extended campaign until the B3 Q4_K/audio/rope parity
and B4 physical Pascal SM61 qualification pass.

The native Voxtral ISQ q4k command remains the validated *load*
baseline (loading and server startup on the Pascal 8 GB GPU), not
a demonstrated audio transcription quality baseline.
