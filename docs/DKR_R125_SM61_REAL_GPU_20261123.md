## Remaining limitations

- `gpu_qualified=false` in the general R1.25 integration audit is
  **correct**: only this **pilot** is physically qualified. It must not be
  silently changed into a full-family or model-level PASS.
- There is **no measured throughput or latency** versus Legacy / Extended.
  DKR is not yet performance-qualified or proven as a complete static
  kernel replacement.
- BF16 tensor initialization and conversion currently need a retained
  Candle generic compatibility path. This is not a purely external DKR
  implementation of all generic tensor operations.
- The host build emitted
  `mistralrs-quant: Compiling 49 of 49 kernels` and
  `mistralrs-paged-attn: Compiling 15 of 15 kernels`,
  despite the persistent Cudaforge directory being present.
  The message does not by itself establish whether all 64 kernels
  were actually recompiled or are cache misses: inspect Cudaforge's
  per-object reuse logs/identities and generated `.cudaforge_cache.json`
  **before another costly rebuild**. The core producer reported
  `Compiling 0 of 15 kernels`. The release build finished in 7m03s.
- Cargo.lock is being reconciled with `cargo metadata` in the user's
  worktree; the PR should incorporate Cargo's resolver-produced lockfile,
  rather than hand-updating git source IDs.
- A later headless-relogin A1/B/A2 protocol must compare identical model
  artifact hashes, numerical logits, prefill/decode lengths, actual
  selected providers, VRAM and GPU clocks under `--release`.
