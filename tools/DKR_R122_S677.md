# S6.7.7 — MMQ attribute counterfactual on the existing archive

S6.7.6 proved the 201 was already present at SIMT entry; all ten batch-9
MMQ codecs failed comparison with B, while B passed 126 checks and
31 telemetry snapshots. Static MMQ calls CUDA_SET_SHARED_MEMORY_LIMIT
unconditionally; the macro ignores cudaFuncSetAttribute return values.
External SM61 MMQ does not mutate that attribute.

Run the new script to observe attribute and launch return codes, then
repeat with only the MMQ MaxDynamicSharedMemorySize request omitted
in a disposable debugger process, with value <=48 KiB on actual SM61.
No CUDA error slot is cleared, no launch status is overridden. The
debugger artificially returns success ONLY for those attribute calls,
so the resulting comparisons are counterfactual, not qualification.
If omission does not resolve the issue, do not assume the macro caused
the launch errors; inspect the trace (registration/context may be at
fault). No source, pin or archive changes. Exit 4 keeps promotion blocked.
